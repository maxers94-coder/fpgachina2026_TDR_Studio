# Stage44 曲线点序与距离刻度对齐修复

2026-10-31。状态：修复已实现、主机模拟与ARM编译通过，实际屏幕对齐仍待短复核。Stage41、Stage43原始发布和本次问题证据均保留。

## 原因

用户的15m测量日志显示全局相关峰lag173，名义距离15000mm；数值测距正常。原生工程两页曲线控件dir均为0、dis均为100。结合实际照片和用户观察，可确认当前屏幕将先收到的数据最终画到右侧，后收到的数据画到左侧。Stage43却把按左到右生成的像素直接顺序上传，而刻度仍由左到右递增，导致水平镜像：全窗15m峰出现在约10m，ZOOM的15m峰出现在约5m。

这是上传点序与原生控件插点方式不一致，不是重新测出了5m，也不是需要改距离拟合系数。此前电脑预览和逻辑FNV检查遗漏了原生控件插点过程，不能据此证明实屏横向位置正确。本次补入了该显示过程。

第二张照片的大量黑色纹理，经用户确认“只有照片里有，肉眼正常”，记录为拍照干涉纹，不作为实际屏幕花屏故障。

原问题数据：`captures/continuous_distance/serial_text_20261031_164613_427/received.txt`。本日志只有J表、两份RAW/相关完整快照及测量/连续摘要，没有本次V查询或建立参考的三份B来源；审查仅验证所含内容，不补造参考来源。J表CRC为70029E0A，SEQ15的256相关值、全局lag173和逻辑绘图一致，SEQ16直通为LOW_RETURN；连续10帧均15000mm，USER STOP正常。问题审查见`pn_dev/work/stage43_mirror_board_audit_20261031.json`。

## 修复

- 逻辑曲线和距离轴仍按从左到右递增保存，仅将透明上传的显示副本倒序，使屏幕插点后恢复正确顺序。
- MEASURE和WAVEFORM两页的AVG32、DIFFERENCE、CORRELATION全部覆盖，避免时间轴也反向。
- 15m正峰应落在全窗15m位置，ZOOM应在右侧15m位置；5m在左侧，10m居中。
- 不改屏幕工程、dir/dis属性、PL、原始采样、相关结果、距离模型或阈值。有效名义范围仍为5～15m。
- HMI_PLOT/FAST_RESULT/CONT_FRAME保留逻辑FNV1A，新增WIRE_REVERSED=1及实际上传副本WIRE_FNV1A，分别核对逻辑像素和线上点序。

上传继续使用当前页面的addt透传，换页/READY仍撤销旧显示归属，参见[淘晶驰官方波形说明](https://www.tjc1688.com/contents/25/201.html)。方向绑定依据是本工程dir0配置和这次实屏观察，不把“dir0必然如此”推广为所有屏幕的通用规则。

302组108713项生产主程序模拟检查通过。新增真实C串口载荷经过“新点插左、旧点右移”的独立FIFO控件模型后，两个页面、FULL/ZOOM、三种视图全部与预期可见像素一致；15m在四种相关视图均与15m刻度对齐，原顺序会失败。独立Python复核四种相关显示的2560点、38快照9728相关/19456逻辑像素及上传副本校验、26连续摘要，原字库/刻度布局检查也通过。

ARM text/data/bss为150471/1904/44928字节；新增768字节固定显示发送缓冲，链接脚本和栈大小不变。以上是主机检查，尚未替代修复后的实际LCD确认。

## 现在操作

1. Vitis选择 **Stage44_WAVEFORM_DIRECTION_FIX_UART0_UART1**，Run。无需重新下载屏幕文件，也不用更改dir/dis。
2. 关闭旧串口窗口，打开`tools/record_serial_text.cmd`。按V确认`FW_STAGE=44`，HMI_INFO应含WIRE_REVERSED=1。
3. 接**主机 → 15m线 → 原直通接头 → 5m线 → 同一个50Ω终端**，在REFERENCE/CAL页完成CAPTURE与15秒内CONFIRM，建立新RAM参考。记录窗口按J保存参考表。
4. 换入同一B4.7串联板，J1朝近端15m线，按SINGLE。先看MEASURE全窗：数值约15m，峰也应在15m附近。再到WAVEFORM选CORRELATION，FULL和ZOOM中15m峰都应对齐15m；ZOOM中15m位于最右侧，不能再跑到最左侧5m。
5. 确认AVG32/DIFFERENCE的时间方向与相关视图一致。返回MEASURE若提示RESULT EXPIRED，按一次SINGLE即可；不重新建参考。只需短复核，不重做整套位置采集。
6. **SINGLE已自动输出本次摘要，之后只按R、C保存完整数据。** 若另做CONTINUOUS，先STOP，再依次I、R、C保存最后结果。每项输出完再发下一项，最后按Q结束记录，将SAVED TEXT路径及峰是否对齐发回。

上一份日志末尾的“I replay被拒绝”来自单次测量后请求连续缓存重放，未破坏已经导出的R/C数据，不代表采集失败。新版说明已区分SINGLE与CONTINUOUS的保存方式。

回退至数值/控制已验收基线可选择Stage41；Stage43保留作问题复现版本，不作为距离轴对齐通过版本。
